# Crit 7

**What was the breakthrough that moved the work forward?**

The breakthrough wasn't technical, it was scoping. I brought in an idea —
"build ANU the integrated portal UTAS has" — that read as exactly the thing
the brief warns against: rebuilding a whole system, and worse, one I have no
real way to integrate with. The first attempt at fixing that went too far
the other way, narrowing to a single tool (tutorial allocation), which would
have thrown away the actual point of the idea. The real move was realising
breadth and depth are separable: the portal can cover seven areas, as long
as only one of them is a real write and everything else reads through it.
Once enrolment was the spine and every other page was a derived read, "don't
rebuild the whole thing" and "feel properly integrated" stopped being in
tension — they were describing the same design.

**What did this work change about who I want to be as a software developer?**

I noticed how much of this week's actual design work happened before any
code — checking an idea against a brief, researching two real systems,
proposing a direction, getting told it was too narrow, and re-deriving a
scope that satisfied both the ambition and the constraint. It would have
been faster to just start building the first idea. The version of me I want
to be treats "is this the right thing to build" as work, not a delay before
the real work — especially when an agent can produce code fast enough that
the bottleneck is entirely in deciding what's worth having it produce.
